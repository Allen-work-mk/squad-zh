# 分布式网格

> ⚠️ **实验性** — Squad 是 alpha 软件。API、命令和行为可能在版本间发生变化。

**试试这个跨机器协调 squads：**
```
设置分布式网格，让我的本地 squad 可以看到 CI squad 的状态
```

**试试这个同步远程 squad 状态：**
```
运行 sync-mesh.sh 从所有远程 squads 拉取最新状态
```

分布式网格让不同机器上的 squads 通过 git 和 HTTP 协调。本地 squads 在本地同步后读取远程 squad 状态。

---

## 什么是分布式网格？

一句话：

> **"文件系统是网格，git 是网格跨越机器边界的方式。"**

Squad 智能体始终读取本地文件。当 squads 生活在不同机器上时，你需要在智能体能看到之前将远程状态具体化到本地。分布式网格通过简单的同步脚本做到这一点 —— 无需服务器、无需联邦协议、无需实时消息传递。

---

## 三个区域

| 区域 | 描述 | 传输 | 复杂度 |
|------|-------------|-----------|------------|
| **1 — 本地** | 同一主机/文件系统 | 直接文件读取 | 零 |
| **2 — 远程-信任** | 不同主机，同一组织 | 从共享仓库 `git pull` | 零新（git 已存在） |
| **3 — 远程-不透明** | 不同组织，无共享认证 | `curl` / HTTP 获取 | ~15 行 shell |

**区域 1（本地）：** `cat ../squad-b/SUMMARY.md` 工作，因为文件在你的磁盘上。

**区域 2（远程-信任）：** Squads 将状态推送到共享 git 仓库。你从该仓库拉取以将他们的状态具体化到本地。

**区域 3（远程-不透明）：** 远程组织在其 HTTPS URL 发布他们 squad 的 `SUMMARY.md`。你用 curl 将它具体化到本地。

---

## 如何工作

### 带同步的智能体生命周期

```
智能体唤醒
  │
  ├─ 同步：git pull（区域 2）+ curl（区域 3）
  ├─ 读取：cat .mesh/**/state.md —— 现在都是本地的
  ├─ 工作：执行任务
  ├─ 写入：更新自己的公告板、日志、drops
  └─ 发布：git push
```

两个新步骤（同步、发布）。两者都只是传输 —— 它们移动文件，不改变文件。

### 什么不改变

- 智能体读取本地文件
- 写入分区（每个 squad 拥有自己的目录）
- 基于拉取的协调
- 最终一致性
- LLM 作为相关性引擎

### 什么改变

远程文件需要到达本地，智能体才能读取它们。
