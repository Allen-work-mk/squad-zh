# 仪式

> ⚠️ **实验性** — Squad 是 alpha 软件。API、命令和行为可能在版本间发生变化。

**试试这个安排团队仪式：**
```
安排每天上午 9 点的站会和每周五的冲刺回顾
```

**试试这个触发工作前设计评审：**
```
在我们开始认证重建之前运行设计评审
```

仪式是在关键时刻发生的结构化团队会议 —— 在多人智能体工作开始前，或在出现问题后。Squad 在需要时自动运行它们。

---

## 内置仪式

### 设计评审

在涉及 2 个以上智能体修改共享系统的多人任务前**自动触发**。

组长主持。每个相关智能体都会生成，在工作开始前对接口、风险和契约发表意见。

```
> 团队，重建认证系统

📋 设计评审完成 —— 由 Ripley 主持
   决策：3 个 | 行动项：4 个
   就 JWT 格式、会话存储策略和端点契约达成一致
```

### 回顾

在构建失败、测试失败或评审者拒绝后**自动触发**。

组长主持一个聚焦的根因分析。

```
📋 回顾完成 —— 由 Ripley 主持
   决策：2 个 | 行动项：3 个
   根本原因：API 响应解析器中缺少空值检查
```

---

## 手动触发

按需运行任何仪式：

```
> 运行回顾
> 运行设计会议
```

---

## 管理仪式

### 创建新仪式

```
> 为代码评审添加仪式
```

### 禁用仪式

```
> 禁用回顾
```

仪式保留在 `ceremonies.md` 中，但不会自动触发。

### 跳过一次仪式

```
> 为此任务跳过设计评审
```

仪式对将来任务保持启用。

---

## 总结

| 操作 | 提示 |
|--------|--------|
| 触发回顾 | `"运行回顾"` |
| 触发设计评审 | `"运行设计会议"` |
| 创建仪式 | `"为代码评审添加仪式"` |
| 禁用仪式 | `"禁用回顾"` |
| 跳过一次 | `"为此任务跳过设计评审"` |

---

## 技巧

- 设计评审防止智能体构建冲突的实现。让它们对多人智能体任务运行。
- 回顾产生写入 `decisions.md` 的决策 —— 它们改进未来工作，而不仅是诊断当前失败。
- 仪式配置位于 `.squad/ceremonies.md`。如果你愿意，可以直接编辑它。
- 仪式与[人类团队成员](human-team-members.md)配合良好 —— 添加人类作为参与者用于审批门禁。

## 示例提示

```
在我们开始前运行设计评审
```

手动为当前任务触发设计评审仪式。

```
对那些测试失败运行回顾
```

启动回顾来分析测试失败并捕获学习。

```
为安全评审添加仪式
```

创建具有自己触发器和参与者的自定义仪式类型。

```
为此快速修复跳过设计评审
```

仅为当前任务绕过设计评审仪式。

```
禁用自动回顾
```

关闭回顾的自动触发，同时保留仪式定义。
