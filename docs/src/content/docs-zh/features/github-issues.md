# GitHub Issues 模式

> ⚠️ **实验性** — Squad 是 alpha 软件。API、命令和行为可能在版本间发生变化。

**试试这个连接到你的积压：**
```
展示此仓库的开放 issues
```

**试试这个开始在特定 issue 上工作：**
```
处理 issue #42
```

**试试这个处理 PR 审查反馈：**
```
PR #24 有审查反馈
```

Squad 连接到你的 GitHub 仓库，从积压获取 issues，将工作路由给正确的智能体，创建分支，实现更改，并打开 PRs —— 所有这些都来自自然语言请求。

---

## 要求

- 安装并认证的 **`gh` CLI**（`gh auth status` 检查）
- 带有 issues 的 GitHub 仓库

---

## 连接到仓库

```
> 连接到 myorg/myrepo
```

Squad 将问题源存储在 `team.md` 中。每个项目只需执行一次。

---

## 查看积压

```
> 展示积压
```

Squad 获取开放 issues 并以表格形式显示：

```
#   标题                        标签        负责人
12  添加用户认证      后端       —
15  修复响应式导航           前端       —
18  编写 API 集成测试  测试       —
```

---

## 处理 Issues

### 单个 issue

```
> 处理 #12
```

协调器将 issue 路由给最适配的智能体。该智能体：

1. 创建分支（例如 `feature/12-add-user-authentication`）
2. 实现工作
3. 打开链接到 issue 的 PR

### 多个 issues

```
> 处理 #12 和 #15
```

智能体并行工作 —— 每个 issue 获得自己的分支和 PR。
