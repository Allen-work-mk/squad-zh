> ⚠️ **实验性** — Squad 是 alpha 软件。API、命令和行为可能在版本间发生变化。


智能体从实际工作中学习并编写技能文件 —— 可复用的模式、约定和技术。技能随时间累积，让每个项目都让你的团队更聪明。

---

## 技能存放位置

```
.squad/skills/{skill-name}/SKILL.md
```

每个技能是一个包含 `SKILL.md` 文件的目录。技能是**团队级知识** —— 不绑定到单个智能体。所有智能体都可以读取和使用任何技能。

> **跨项目可移植**：技能随你的团队导出和导入。当你将训练好的团队移动到新仓库时，他们积累的所有知识都会随之而来。

---

## 技能类型

### 入门技能

初始化 Squad 时捆绑。前缀为 `squad-`（例如 `squad-conventions`）。这些编码了使用 Squad 的基线模式。

### 会话恢复

`session-recovery` 技能教智能体查找和恢复中断的 Copilot CLI 会话。当会话中断（终端崩溃、网络断开、机器重启）时，正在进行的工作可能未完成。此技能使用 `session_store` SQL 查询检测被遗弃的会话、检查检查点进度并恢复工作。查询模式和示例参见 [`.squad/skills/session-recovery/SKILL.md`](https://github.com/bradygaster/squad/blob/dev/.squad/skills/session-recovery/SKILL.md)。

###  earned 技能

由智能体从你的项目实际工作中编写。当智能体发现可复用模式 —— 部署策略、测试技术、API 集成方法 —— 时，它会编写一个技能文件。

---

## 信心生命周期

 earned 技能有一个反映其经过多少实战测试的信心级别：

| 级别 | 含义 |
|-------|---------|
| **低** | 首次编写 —— 基于单一经验 |
| **中** | 在多个上下文中成功应用 |
| **高** | 成熟建立，持续可靠 |

信心只升不降。达到 `高` 的技能会保持在那里。

---

## 技能如何使用

1. **工作前**，智能体读取与手头任务相关的技能文件
2. **基于技能的路由** —— 协调器在决定生成哪个智能体时检查可用技能。具有相关 earned 技能的智能体可能比没有的更受青睐。
3. **工作后**，智能体可能根据学到的内容编写新技能或更新现有技能

## 示例

成功设置 CI 流水线后，智能体可能创建：

```
.squad/skills/ci-github-actions/SKILL.md
```

```markdown
# 使用 GitHub Actions 进行 CI

**信心：** 中

## 模式
- 使用 `actions/checkout@v4` 访问仓库
- 使用 `actions/cache@v4` 缓存 node_modules，使用 package-lock.json 的哈希
- 将 lint、test 和 build 作为独立任务运行以并行执行
- 使用 `concurrency` 组取消被取代的运行

## 学习来源
- 初始 CI 设置（会话 3）
- 构建缓慢后的流水线优化（会话 7）
```

## 技巧

- 技能随时间累积。成熟项目有涵盖测试模式、部署程序、API 约定等的技能。
- 入门技能（`squad-*`）在升级时被覆盖。 earned 技能永远不会被触碰。
- **技能在整个团队共享** —— 任何智能体都可以读取任何技能。它们存储在扁平的 `.squad/skills/` 目录中，不是按智能体的文件。
- 如果你想植入知识，可以手动编辑技能文件（例如，将你团队现有的约定粘贴到 `SKILL.md` 中）。
- **技能在导出/导入中幸存** —— 你团队累积的知识在项目间完全可移植。
