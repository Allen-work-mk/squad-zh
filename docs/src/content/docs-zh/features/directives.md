# 指令

> ⚠️ **实验性** — Squad 是 alpha 软件。API、命令和行为可能在版本间发生变化。

**试试这个建立团队编码标准：**
```
从现在开始，所有测试必须使用 Jest 而不是 Mocha
```

**试试这个设置格式化规则：**
```
在 TypeScript 中始终使用单引号
```

**试试这个执行工作流策略：**
```
永远不要直接提交到 main
```

指令是在会话间持久存在的团队规则。当你说"始终"或"绝不"时，Squad 捕获它并写入团队的永久记忆。每个智能体在工作前都会读取这些。

---

## 指令如何工作

指令是团队跨会话记住的偏好、规则或约束。当你说"始终做 X"或"绝不做 Y"时，Squad 将其作为指令捕获，写入决策收件箱，然后 Scribe 将其合并到 `.squad/decisions.md` —— 团队的永久记忆中。

## 指令如何工作

1. **信号词检测** —— 协调器监听："always"、"never"、"from now on"、"remember to"、"don't"、"make sure to"。
2. **捕获** —— 指令写入 `.squad/decisions/inbox/{timestamp}-{brief-slug}.md`。
3. **Scribe 合并** —— Scribe 在下一个协调周期将收件箱文件整合到 `decisions.md`。
4. **智能体感知** —— 所有智能体在开始工作前读取 `decisions.md`。指令塑造行为。

## 信号词

| 短语 | 示例 |
|--------|---------|
| "always" | "始终使用 TypeScript 严格模式" |
| "never" | "绝不直接提交到 main" |
| "from now on" | "从现在开始，所有提交都要以前缀 issue 号开头" |
| "remember to" | "记住在推送前运行测试" |
| "don't" | "不要使用 var —— 只用 let 和 const" |
| "make sure to" | "确保记录所有公共 API" |

## 指令范围

指令可应用于：

- **编码风格** —— 格式化、命名约定、语言特性
- **工具偏好** —— 检查器、格式化器、测试运行器
- **工作流规则** —— 分支命名、提交消息、PR 模板
- **范围约束** —— "不要碰 legacy/ 目录"、"只处理 v2 特性"
- **评审要求** —— "始终让组长评审安全变更"

## 决策收件箱

新指令作为单独文件进入 `.squad/decisions/inbox/`：

```
.squad/decisions/inbox/
├── 2024-01-15-1420-single-quotes.md
├── 2024-01-15-1435-no-friday-deploys.md
└── 2024-01-15-1450-api-test-coverage.md
```

Scribe 定期将它们整合到 `decisions.md`：

```markdown
# 团队决策

## 编码风格

### 字符串使用单引号
在 TypeScript 中使用单引号表示字符串字面量。除非需要转义，否则避免双引号。

## 测试

### API 集成测试覆盖
每个新 API 端点需要至少一个覆盖快乐路径的集成测试和一个错误用例。

## 发布流程

### 周五不部署
不要在周五触发生产部署。只安排在周一至周四。
```

## 指令冲突

当新指令与现有指令矛盾时：

1. **Scribe 检测冲突** —— 在合并期间检查语义重叠。
2. **用户提示** —— "新指令与现有规则冲突：{旧规则}。替换、合并或跳过？"
3. **解决** —— Scribe 根据你的选择更新 `decisions.md`。

## 查看指令

> "给我看看团队指令"

协调器显示 `decisions.md` 内容。

> "我们对测试的规则是什么？"

协调器搜索 `decisions.md` 中与测试相关的指令。

## 移除指令

> "移除周五不部署规则"

Scribe 编辑 `decisions.md` 并移除该部分。

或直接编辑 `.squad/decisions.md`。

## 智能体指令合规

智能体不受指令的硬约束 —— 它们是上下文感知的指南。如果智能体违反指令：

- **评审者拒绝** —— 组长或测试人员在评审期间标记它。
- **用户反馈** —— 你说"这违反了我们风格规则"，智能体进行修订。

指令塑造行为，但不替代代码评审或代码检查。

## 示例提示

```
始终使用 Prettier，单引号，无分号
```
创建编码风格指令。所有智能体都会相应地格式化代码。

```
绝不在 TypeScript 中使用 `any` 类型 —— 始终定义显式类型
```
建立类型安全指令。智能体会避免 `any` 并使用正确的类型。

```
从现在开始，所有提交消息必须遵循 Conventional Commits 格式
```
设置工作流指令。智能体会将提交格式化为 `feat:`、`fix:`、`docs:` 等。

```
记得为每个面向用户的变更更新 CHANGELOG.md
```
创建发布流程指令。智能体会在适当时添加变更日志条目。

```
确保所有安全相关的 PR 在合并前由组长评审
```
建立评审要求。协调器会将安全 PR 路由给组长审批。
